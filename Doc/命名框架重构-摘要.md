## 已确认的行为

| 事项 | 已确认的方向 |
| --- | --- |
| 原版命名 | 覆盖原版实际存在的全部自动命名入口，包括生物个体、生物分类、社会对象，以及战争、装备、书籍、格言、世界名等；以命名学为主要接入路径。 |
| 内容与验收 | 默认内容符合对象特点，姓氏按适用情况使用；重名要求按类型确定，人名允许重复。验收检查覆盖、有效性、长度、重复情况和继承正确性，并抽样判断命名是否合适。 |
| 默认风格 | 整体用中文呈现，保留物种特色，追求自然易读；这些是可调整的初始默认方案，娱乐和梗名作为可选包提供。 |
| 原版模板入口 | 当前原版仍使用的模板命名入口属于游戏适配范围，主体命名以命名学为主；旧中文名模板格式兼容暂缓。 |
| 旧版兼容范围 | 旧存档迁移、旧包格式导入和第三方改版的迁移适配暂缓，优先完成新框架；第三方改版保留为需求参考。 |
| 文化 | 决定命名结构和继承习惯，允许玩家按文化编辑。 |
| 配置来源 | 生物使用自身文化与语言；新建城市、文化、宗教等使用创建者；书籍和装备使用作者或制造者；军队和船只优先所属城市、其次所属国家；联盟使用发起国；战争按战型指定的命名方；没有适用来源时使用世界默认方案。 |
| 规则骨架 | 每个文化的每种命名类型可以有多条规则，每条包含使用条件、抽取权重和有序组成部分；性别、身份、物种等差异主要通过条件控制，编辑器提供筛选。 |
| 统一模型 | 规则以结构化数据保存，每条规则和每个部件拥有稳定标识；命名包、文化编辑、预览与实际生成共用同一模型。 |
| 生成失败 | 必需部件缺失则该规则失败，可选部件允许省略；有限重试后依次使用类型默认方案和接入方回退，保留失败原因，避免写入半成品或将错误占位符当成成功结果。 |
| 语言 | 决定各部分使用的词库；默认以稳定的偏好加权形成语言差异，玩家可以排除词条或限定子词库。 |
| 初始化与分化 | 新文化有来源时继承方案选择、继承习惯和手工调整，之后独立管理；新语言有来源时继承词库方案并形成相近但不同的稳定偏好；无来源时按世界默认与适用条件选择，已有配置默认不随时间自动漂移。 |
| 扩展类型 | 其他模组可以增加功法、法术等命名类型，并与原版类型一样支持文化内编辑和预览。 |
| 扩展接口 | 类型可以声明输入、词汇用途、自定义条件与组成部件、预览样例、校验和回退要求；结构仍由文化规则决定，名字与组成部分由调用模组写回对象。 |
| 包装卸 | 已有名字保留，之后新生成的名字立即使用当前启用的命名包配置。 |
| 包组合 | 安装与启用分开；文化和语言分别选择基础方案，按范围叠加追加、替换或排除内容；冲突按玩家设置的优先级处理，并显示最终来源。 |
| 词条与权重 | 同一词条被多个词库引用时只算一次，采用最高有效来源倍率；同字但含义不同的词条独立保留，界面按文字分组。倍率是词条加权，不是词库总概率份额。 |
| 排除 | 可排除当前语言、当前用途下的全部同字词条，也可指定词条；包不能越过玩家排除。 |
| 包冲突与依赖 | 多包修改同一字段按玩家优先级处理，同级不同值明确报冲突；缺失模组只使相关内容不可用，其他内容继续，编辑保留。 |
| 修改分发 | 默认将玩家修改导出为只包含修改与新增内容的补充包，声明基础包依赖；允许另行制作独立完整方案。 |
| 配置范围 | 包文件全局共享，新世界继承全局默认预设；每个世界独立保存启用包、优先级、绑定和玩家修改，名字与姓氏随对象保存。包内容使用当前安装版本。 |
| 玩家编辑 | 按实际修改的字段保存覆盖；新增内容独立保存，禁用状态持续生效，未修改部分跟随包更新，并提供重置操作。 |
| 顺序与新增部件 | 已自定义的输出顺序保持不变，包新增的输出部件标为待加入，由玩家选择是否采用；未修改顺序的规则自动跟随包更新，既有部件的未修改设置继续更新。 |
| 缺失内容 | 包缺失时保留修改并明确标记，重新启用后恢复；原规则或部件被移除时提示处理，允许重新绑定或恢复。 |
| 姓氏 | 继承的姓氏原样保留；文化、语言变化和包切换不自动改姓，新语言影响新取的名，改姓另行操作。 |
| 继承方案 | 以孩子出生时采用的文化决定继承方式，可配置优先父姓、优先母姓或从任一亲代随机继承；完整继承一位亲代的姓氏，不拆分或拼接双方姓氏。无文化时使用适用于该生物的默认方案。 |
| 继承边界 | 单亲继承该亲代；优先一方确实无姓时使用另一方已有姓氏；使用姓氏的亲代尚未取姓时先确定并保存，再继承；无亲代或亲代都不使用姓氏时，孩子按需建立新姓氏。特殊繁殖可由模组补充亲代关系。 |
| 首次命名 | 出生时确定并保存姓氏，首次需要姓名时生成完整名字。 |
| 复制与转变 | 克隆复制原姓名、姓氏及组成部分；变为僵尸或骷髅时保留原姓名和姓氏；进化或升格保留个人姓名，产生新亚种时单独为亚种命名。 |
| 事件改名 | 军队换国时自动名字按新归属更新，装备重铸时自动名字按重铸结果重取；这两类事件保留玩家手改名字。文化、语言和包切换仍保留已有名字与姓氏。 |
| 编辑界面 | 重设计统一的“命名管理”入口，设文化规则、语言词库、命名包、世界方案四个工作区；文化和语言页面采用对象列表、编辑区和常驻预览的布局。 |
| 预览 | 可调整性别、物种、元素、境界等输入，查看名字各部分来源与失败原因；使用模拟数据或对象信息副本，不修改世界状态。 |
| 编辑生效 | 采用草稿、预览与检查、应用的流程；草稿修改即时更新预览，应用后影响新命名；页面切换保留草稿，支持撤销、重做、局部重置、保存草稿和放弃修改。 |
| 推进方式 | 当前先沉淀讨论和决策，讨论充分后再全面重构。 |

## 当前框架模型

一次命名由命名类型与对象信息、文化规则、语言词库和需要继承的名字部件共同决定。命名包提供默认内容，玩家修改作为独立数据保存。

| 部分 | 负责的内容 |
| --- | --- |
| 命名类型 | 声明给什么对象命名，需要哪些信息，如何预览和校验。 |
| 文化规则 | 决定名字由哪些部分组成，以及部件顺序、条件与继承习惯。 |
| 词汇用途 | 用“姓氏”“名字用字”“元素修饰”等用途连接命名结构与实际词库。 |
| 语言 | 决定各用途的词库来源，并形成稳定的用词差异。 |
| 命名包 | 提供词库、规则、语言方案、默认绑定和可选择的风格预设。 |
| 生成结果 | 返回名字及需要保留的组成部分，生成过程和持久化写入分开。 |

这些职责是后续设计的基础，具体文件格式、接口和存储结构仍需讨论。

## 下一轮讨论重点

产品行为已覆盖命名来源、继承与生命周期、包组合、词库权重及分发。接下来按重构计划的阶段 0 收敛接口和格式，并核对构建与游戏版本；具体技术参数可以在对应阶段落实，无需重新逐条确认已定行为。

1. 在已确认的布局与草稿应用流程上，细化规则与词库编辑控件、预览输入、应用范围和具体交互。
2. 在已确认的规则骨架与失败处理上，细化条件表达、部件与引用、重试上限和默认方案配置，以及当前原版字形的接入。
3. 将已确认的去重、最高来源倍率、优先级冲突、依赖隔离和补充包导出落实为格式、校验与界面交互。
4. 在已确认的初始化与分化方式下，细化默认匹配、稳定偏好算法与差异幅度、保存方式，以及包更新后的变化。
5. 细化特殊繁殖的亲代关系，以及姓氏初始化的具体时机。
6. 在已确认的扩展边界上，确定字段与参数类型、注册与依赖关系、校验与回退的具体接口。
7. 字段覆盖与列表编辑怎样合并，缺失类型怎样保存和恢复，以及具体回退接口、世界数据保存与新框架的数据版本标记。
8. 根据源码盘点具体覆盖清单，细化默认内容、各类型的长度与重名要求、样本检查方法和验收阈值。

详细问题和候选方向见[待讨论问题](命名框架重构/设计讨论.md#待讨论问题)。

## 暂缓事项

旧存档迁移、旧 TXT 和 JSON 内容的导入转换，以及第三方改版代码的迁移适配，暂不纳入本轮重构。下载目录中的改版包继续用于分析词库、风格切换和内容分发需求。

当前原版游戏的命名接入和新框架内的存档、包切换行为仍属于本轮范围。
