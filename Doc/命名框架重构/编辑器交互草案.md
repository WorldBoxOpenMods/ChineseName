# 编辑器交互草案

文化档案中按部件编辑人名和城市名的新版交互，见[命名学部件编辑方案](命名学部件编辑方案.md)。

更新日期：2026-10-24。

本文用“修改一个文化的人名规则”走通编辑、预览、应用、切换命名包与读档，再检查语言编辑和扩展类型是否能使用同一套交互。已确认的产品行为见[设计讨论](设计讨论.md)，模块职责见[架构与执行流程草案](架构与执行流程草案.md)。本文新增的控件、导航、应用粒度和草稿保存细节均为候选方案，尚未实现到游戏中。

配套提供[命名管理交互原型](原型/命名管理交互原型.html)。原型可在浏览器本地打开，使用内置示例数据和简化抽取逻辑，不连接游戏，也不代表正式生成器、默认词库或最终美术。刷新页面会重置演示；原型中的保存和读档只模拟本次页面会话。

## 先明确编辑范围

建议每页顶部固定显示“编辑谁、编辑什么、影响谁”。文化页面选预览语言不会改变文化与语言的实际关系，语言页面选预览文化也不会改变世界中的归属。

| 当前工作区 | 实际编辑对象 | 预览还需选择 | 应用影响 |
| --- | --- | --- | --- |
| 文化规则 | 某文化中某命名类型的规则，以及文化的继承习惯。 | 使用哪种语言、物种与类型输入。 | 该文化之后的相应命名；继承习惯用于之后的出生。 |
| 语言词库 | 某语言的词库绑定、偏好、排除和新增词条。 | 哪个文化、哪种命名类型和对象输入。 | 使用该语言生成相应用途词汇的对象，可能跨多个文化。 |
| 命名包 | 查看已安装内容、制作与导出内容；与世界启用设置分开。 | 包的样例或指定文化、语言。 | 编辑与安装不等于在当前世界启用；包版本更新仍按已确认的内容更新规则处理。 |
| 世界方案 | 当前世界的启用包、优先级和默认绑定。 | 示例文化、语言与对象输入。 | 应用范围内之后的新命名；已有名字保留。 |

世界默认方案和新世界默认预设应有不同的范围标签，避免玩家以为改了当前世界就会改变所有存档。导出预设与应用到另一个世界应作为明确操作。

## 文化页面草图

```text
命名管理 · 当前世界
[文化规则] [语言词库] [命名包] [世界方案]

编辑：河谷文化 / 人名     基础方案：中式基础
影响：该文化之后的人名；已有名字保持原样

文化列表          规则与继承设置                 常驻预览
搜索与筛选        启用  名称  条件  权重          预览语言：汉语
                  ● 双字名  通用   4             性别、物种等输入
河谷文化          ● 单字名  通用   1             模拟出生 / 已确定姓氏
海岸文化
                  所选规则的部件顺序             李青川  李明月 ……
                  [姓氏] [名字用字] [名字用字]    展开：部件及词汇来源
                  [添加部件]                     提示、失败原因与回退

                  继承习惯：优先父姓             预览组成：本文化草稿
                  [查看本规则使用的词汇]         ＋语言和世界的生效配置

[撤销] [重做] [重置选定字段] [放弃修改] [保存草稿] [应用当前文化]
```

布局是信息组织示意，具体尺寸、图标与游戏美术适配后续确定。部件顺序支持拖动，同时提供上移和下移操作；在暂不支持拖动的原型中使用按钮演示。

当前编辑对象固定在对象列表选择。文化页的预览区显示当前文化，只允许调整预览语言等输入；语言页则固定当前语言，允许选择预览文化。预览控件不能悄悄切换正在编辑的对象。中等宽度保留编辑与预览并列，窄窗口用顶部预览摘要保持修改结果可见。

规则列表建议展示启用状态、可读名称、条件摘要、权重与状态。选中后编辑条件和部件；复杂条件可展开为“全部满足／任一满足”等分组。多数玩家无需阅读 JSON 或输入内部标识。

部件设置根据所选操作显示参数，例如固定文字、按用途取词、引用已有姓氏或引用其他部件。只作为依赖的辅助部件与直接输出的部件分别展示，避免玩家误以为每个定义都会拼进名字。

## 完整操作案例

### 一、进入并修改文化结构

玩家从文化窗口进入命名管理，自动选中该文化；从全局入口进入则保留上次选择。先选“河谷文化／人名”，查看当前基础方案和规则来源。

把双字名权重从 4 改为 8，或调整该规则的组成顺序后，立即出现“未应用”状态，右侧预览采用草稿。此时实际世界继续使用此前生效的配置。

只改权重就只产生权重覆盖；调整顺序保留各部件身份。重置某字段意味着重新跟随当前包默认值，不是恢复到编辑器第一次打开时的旧值。新增或复制规则形成玩家自己的内容，禁用包规则保留明确的禁用状态。

### 二、检查预览

预览建议提供两种输入：模拟新对象，以及复制实际对象的命名信息。复制不会调用真实对象的取名、初始化姓氏或保存流程。

对于人名，“模拟出生”使用模拟亲代与文化继承习惯；“已有确定姓氏”直接使用输入姓氏。这样修改继承习惯时有对应示例，也能检查李姓等已有姓氏不会被语言或包切换覆盖。

预览展示一批名字，点击某个结果查看规则、组成部分、词库与词条来源，以及哪些值由玩家覆盖。固定输入和抽样种子可用于前后比较，“换一批”单独更换预览种子。回退结果应标明回退原因，不能把它展示为自定义规则正常生效。

### 三、需要改用词时切到语言页面

从“名字用字”部件进入“查看使用的词汇”，跳到当前预览语言对应的用途，保留文化草稿，并携带预览文化和类型。页面顶部说明修改该语言会影响哪些文化使用的命名配置。

语言页面允许筛选词库和词条、调整偏好、排除或限定子词库、添加词条，并区分默认值与玩家修改。词库中的来源词条不直接原地修改全局包；个人调整保存到当前语言，制作可分发内容时另行导出命名包。

建议默认预览“当前对象草稿＋其他对象的已生效配置”。语言页应用后，回到文化页时使用新的已生效语言配置和原有文化草稿。若以后提供多对象合并预览，需要显式标出所有参与草稿，不能让玩家误以为它们已生效。

### 四、应用

建议普通应用只提交当前对象的草稿：文化页应用当前文化，语言页应用当前语言，世界方案页应用当前世界方案。其他页面尚未应用的草稿继续保留，不能顺带提交。

应用按钮旁显示修改数、目标与影响范围。结构与参数错误定位到具体控件，保留草稿并继续运行旧配置；缺失依赖按已确认的标记和回退方式处理。若需要跨多个对象一起应用，可另设“查看全部草稿”入口，让玩家选择参与对象并检查依赖，不要求每次普通应用都弹确认框。

应用之后，预览与随后产生的新名字使用新配置。已有名字不变；某文化的人名结构调整不会把所有使用同一语言的文化结构一起修改。语言词库修改则可以影响多个文化之后的新名字。

### 五、切换或更新命名包

在世界方案页调整包启用或顺序时，先形成世界方案草稿并显示影响范围，应用后才影响新的命名。安装与世界启用仍保持分开。

| 包变化 | 编辑器反馈 |
| --- | --- |
| 包更新未编辑的词条或字段 | 显示当前来源与有效值，按既定规则跟随更新。 |
| 包更新玩家改过的权重 | 保留玩家权重，可展开比较当前默认值。 |
| 包给未改顺序的规则增加输出部件 | 按新的默认顺序显示与预览。 |
| 包给已改顺序的规则增加输出部件 | 在“待加入”区显示新部件，提供加入、选择位置和恢复默认顺序。 |
| 包或部件缺失 | 保留覆盖与草稿，显示缺失来源及当前回退；不要自动匹配同位置条目。 |
| 部件类型改变，旧覆盖不适用 | 显示冲突，提供重置受影响字段或重新绑定兼容目标等候选修复操作。 |

“重新绑定”与“保存为独立规则”的具体修复步骤仍需细化，原型只演示新增输出部件和包缺失恢复。

词条按显示文字分组、展开来源和精确排除，同级冲突的展示与可选模组依赖隔离，可结合[合并规则候选方案](规则与数据模型草案.md#词条身份与重复引用)继续设计。现有原型尚未实现多词库倍率和完整包冲突交互，不能用原型的简化抽取逻辑代替这些规则。

### 六、保存、退出与读档

已应用的配置随世界正常保存。建议显式“保存草稿”保存未应用的编辑，并与对应世界和目标对象关联；存草稿不会使它生效。普通页面切换只保留当前会话草稿，不额外要求确认。

读档后恢复已应用配置、已保存的草稿和已确定的名字。包内容继续来自当前安装版本，不能通过读档退回旧词库或包版本。草稿应记录它基于哪份生效配置；若期间包或目标已变更，重新解析并显示冲突，避免覆盖较新的设置。

切换世界或退出时怎样处理尚未显式保存的草稿，需要在游戏窗口与存档接入时确定；不能默默把草稿当成生效配置。原型未实现跨版本草稿合并或真正写入磁盘。

## 扩展类型怎样进入同一界面

Cultiway 注册法术类型后，在文化的类型列表中出现可读名称与图标。类型提供元素、形态、境界等输入声明，预览据此生成控件；规则仍使用条件、权重和部件编辑。

自定义部件按声明提供参数控件和说明。只有需要超出通用控件能力时，才考虑可选的专用编辑组件。类型或部件所属模组缺失时，保存原数据并显示缺失状态，不丢弃规则，也不把未知字段改写为空值。原型暂不演示法术控件，先验证人名路径。

## 原型可检查的场景

| 操作 | 应观察到什么 |
| --- | --- |
| 修改文化权重与顺序 | 预览改变，已生效的配置和已有名字不变。 |
| 切换到另一文化再回来 | 当前文化未应用的草稿仍存在。 |
| 排除共享语言中的词条 | 语言草稿预览改变；应用后两个使用该语言的文化都会使用更新后的词库。 |
| 调整继承习惯 | 模拟出生的姓氏按规则变化，切到已有姓氏时保持输入姓氏。 |
| 只应用一个对象 | 其他对象的草稿保留，实际新增演示生物使用已生效配置。 |
| 调整包后应用 | 新名字使用有效包，已有人名不重取。 |
| 先改顺序，再模拟包更新 | 新称号部件显示为待加入；另一未改顺序的文化直接采用新默认顺序。 |
| 模拟包缺失和恢复 | 编辑保留，缺失时清楚显示回退，恢复后重新可用。 |
| 保存草稿、模拟存档和读档 | 恢复显式保存的编辑与已生效配置；包版本仍为当前安装状态。 |

这些是交互设计的检查场景，原型运行通过不等于正式框架已经实现或通过游戏内验收。

## 浏览器体验与修正记录

2026-10-24 使用本机 Chromium 的独立临时会话，通过浏览器调试接口实际执行鼠标点击、键盘输入和选择，并检查页面截图。没有使用日常浏览器的会话数据，也没有连接游戏。

| 实际发现的问题 | 已做的修正 |
| --- | --- |
| 输入词条后点击添加，失焦触发无关重绘，文本丢失，添加失败。 | 未处理的输入变更不重绘页面；支持点击和回车添加，并把焦点留在新增词条输入框。 |
| 预览文化或语言的下拉框同时切换正在编辑的对象，操作范围容易被误解。 | 当前编辑对象在预览中只读，使用对象列表切换；另一维度继续作为预览输入。 |
| 中等宽度把整个预览排到长编辑区之后，无法边改边看。 | 中等宽度让对象列表横排，编辑与预览继续并列；更窄窗口提供常驻顶部的预览摘要。 |
| 权重已经改为草稿，字段旁仍标“来自方案”；重置未修改字段或撤销到原值还显示未应用。 | 数值输入即时更新来源标识；无变化的重置不创建编辑，撤销回到生效配置后取消未应用状态。 |
| 操作反馈在动作栏外，容易离开视野；应用按钮的对象范围不够直接。 | 把反馈放进动作栏，按钮分别显示应用当前文化、当前语言或世界方案。 |

修正后通过 20 项浏览器流程检查，覆盖词条点击与回车添加、已有姓氏输入、草稿隔离、共享语言影响、应用范围、撤销与错误提示、新增部件、包缺失与恢复、模拟存读档和键盘选择。检查期间未发现页面脚本异常。

另检查 1440、1280、960、600、360 像素宽度，未发现横向溢出，并查看编辑区、并列预览和窄窗摘要的实际截图。保留[桌面编辑截图](原型/截图/文化规则-桌面.png)与[窄窗编辑截图](原型/截图/文化规则-窄窗.png)供讨论。

这些结果验证的是本地交互原型。游戏内窗口、美术、真实命名规则、模组扩展控件、文件保存及跨版本草稿合并仍需后续实现和验证。
