# 命名框架实现与验证

这里记录当前代码的接口和验证方式。[分阶段计划](分阶段重构计划.md)和[设计讨论](设计讨论.md)保留产品行为及历史方案。草案中的 JSON 示例不作为 v1 格式使用。

文化档案「命名学」把生物、城市、国家、家族、氏族、文化、语言、宗教、战争、联盟、军队、书籍、格言、装备、谋划和模组类别放在同一个分类容器，按宽度自动换行。原版补充类别、图标、预制条件和专属字形用同一份类别声明。原版词组、分隔符和模组字形使用同一个盘，预览和语言对照只读。命名预设上的新编辑保存在同一地图的模组文化设置里，文化分化继承这些设置。亚种、世界和造物主使用世界级命名规则。

战争用战型指定的一方国家作为文化来源，联盟用发起国，军队优先用驻地城市，书籍用作者。格言沿用其国家、氏族或联盟的文化来源；氏族还未产生首领时可沿用创始人的文化。传奇装备和重铸优先用制作者的文化，缺少制作者时取出产国的文化。这些规则用于实际生成或重铸时，已有名称和自定义名称按原版行为保存。

## 其他模组接入

在模组清单的 `Dependencies` 中加入 `CHINESENAME`。在加载时构造 `NamingCategory`，用 `NameType` 声明带命名空间的稳定 ID、界面名称及输入字段。可在同一个描述中指定默认命名包、命名学图标、预制条件和专属字形，最后调用 `NamingApi.Current.RegisterCategory`。默认包用 `Defaults` 提交，加载后自动启用。

```csharp
var category = new NamingCategory(new NameType("spell-example:spell", "法术", new[]
{
    new InputField("element", InputKind.Text, example: "fire"),
    new InputField("form", InputKind.Text, example: "blade")
})) { CultureIcon = "ui/Icons/iconFire", Defaults = spellPack };
category.Values("element", "元素", new Dictionary<string, string> { ["fire"] = "火" });
category.InputGlyph("spell-example:element", '\uE260', "element", "元素", "ui/Icons/iconFire",
    poolPrefix: "spell-example:element");
NamingApi.Current.RegisterCategory(category);
```

调用方负责把角色、功法、法术等领域对象转换成 `NameRequest`，以及在 `Success` 为真时存储 `Text`。失败时可读 `Status` 和 `Diagnostics`，并使用调用方现有的回退。游戏里的调用应在主线程执行。

```csharp
var request = new NameRequest(
    "spell-example:spell", seed: 42, culture: cultureId, language: languageId,
    inputs: new Dictionary<string, object> { ["element"] = "fire", ["form"] = "blade" });
var result = NamingApi.Current.Generate(request);
if (result.Success) SaveName(result.Text);
```

`Preview` 接收同样的请求及可选的世界草稿。结果的 `Parts` 按稳定部件 ID 提供组成文字。命名不会设置游戏对象的名称。候选提供者通过 `RegisterProvider` 注册，每次请求至多读取一次，最多接收 128 个候选；提供者应稳定且无副作用。`Text`、`Integer`、`Flag` 是当前可声明的输入类型，原版和模组类型从同一注册表进入编辑窗口。

Cultiway 以可选依赖接入。共享法术使用世界级规则，有明确创法者的构建使用其文化和语言。法术词素从 Cultiway 已有的元素、形态、运动和词条资源转换成中文名词库。Cultiway 保留原规则回退及后续 AI 命名流程。东方人族通过 `RegisterDefaultPack` 提交种族规则，人物、城市、国家、文化和语言都走框架已有的入口。新增种族也可以复用这个做法，无需登记一个新的人物命名类型。

输入字段可以提供 `example`，让编辑器第一次预览就有有效输入。词库部件可以声明 `poolInput`，将已声明的文本字段作为池编号后缀。例如 `pool: "cultiway:spell-element"` 和 `poolInput: "element"` 会用输入 `semantic.element.fire` 选择 `cultiway:spell-element.semantic.element.fire`。这些词库仍能在语言页调整。

类别可以通过 `PrepareContext` 声明一段输入转换。例如由刃形推导器物词根。转换收到输入副本，可写入已登记的字段，返回 `false` 表示组合无效。实际生成、原版预览和条件示例共用这段转换。回调抛出异常时，取名结果为 `GenerationStatus.ContextError`，诊断附有类别 ID 和异常类型。转换应只根据输入生成结果。原版书籍、装备、谋划和联盟用它补齐互相关联的字段。

提供 `CultureIcon` 后，`RegisterCategory` 会把模组类别登记进原版「命名学」。`Description` 可省略。分类按钮与原版其他类别共用同一个字形盘，使用输入字段的 `example` 预览。默认规则的词库、固定文字、输入和候选列表可以投影为词组，词组留空时继续按实际请求取词。直接调用候选提供者或复制其他部件的规则仍可通过结构化规则生成。Cultiway 的「修仙法术」用火球作预览示例，实际取词仍由法术的语义和创法者的语言决定。

Cultiway 的默认法术排列中，词组 I 到 IV 依次使用元素、主要词条、运动和形态。可以在新词组写入「诀」，只排列元素词组与这个新词组。元素词组留空，同一种火球即可随语言取成「炎诀」或「火诀」。

用 `Values(field, label, values)` 为已声明的文本字段添加预制条件。字典的键与实际 `NameRequest` 使用的值一致，字典的值是玩家看到的名称。需要判断输入是否有值时使用 `Presence(field, label, present, absent)`。Cultiway 从自己的法术语义表登记「元素」和「形态」，玩家在预制条件盘里点选「火」与「球状」，再用与、或、非和括号组合。

用 `InputGlyph` 声明读取输入或按输入选词库的原版字形。下面的字形接到 `semantic.element.fire` 时，按当前语言从 `cultiway:spell-element.semantic.element.fire` 抽词。

```csharp
category.InputGlyph("cultiway:spell-element", '\uE240',
    "element", "法术元素", "ui/Icons/iconFire", poolPrefix: "cultiway:spell-element");
```

字形用带命名空间的 ID 和发布后固定的私用区短码，重复的 ID 或短码会报错。省略 `poolPrefix` 时直接使用请求输入。给前缀加尾连字符可引用历史词库 ID，例如 `chinesename:book-` 和题材 `history` 组合成 `chinesename:book-history`。可以另指定 `fallbackPool`，在输入或对应词库缺失时从中取词。

战争请求的 `kind` 是原版战争类型 ID，`attacker` 和 `defender` 是宣战时双方的国名，`origin` 及文化和语言取自该战争类型指定的命名方。例如 `normal` 以进攻国为来源，`rebellion` 以防守国为来源。默认规则按类型选择称谓，补充包可以把双方国名放在同一条规则里。书籍请求的 `kind` 是原版书名模板 ID，例如 `book_name_history`。

### 扩充已有类别

在加载时构造 `NamingCategoryExtension`，指定已有类别的 ID，再用 `ExtendCategory` 一次登记输入、预制条件和字形。原来的页签、命名规则和输入继续可用。输入 ID 在该类别内唯一，字形 ID 和私用区短码在原版字形库内唯一。

```csharp
var war = new NamingCategoryExtension("worldbox:war");
war.Input(new InputField("border-place", InputKind.Text, example: "澄江"));
war.Presence("border-place", "边境地点", "有地点", "无地点");
war.InputGlyph("example:border-place", '\uE261', "border-place", "边境地点", "ui/Icons/iconCityList");
NamingApi.Current.ExtendCategory(war);
```

调用方可在 `NameRequest.Inputs` 提供新输入。原版战争入口还可通过 `WorldNamingInputs.RegisterWarInput` 读取当前战争、命名方和对方国家。创建时战争参数为空，已有战争会传入实际对象。字段的 `example` 供原版命名学预览使用。文化外称附属模组用这条路径提供「对方国号外称」。

对原版命名请求，先通过 `ExtendCategory` 声明字段，再用 `WorldNamingInputs.RegisterInput(type, field, read, scoped: true)` 登记取值方式。回调可读取当前可用的对象、创始者、文化、语言和地块，只读取游戏状态。对象尚未创建、作者缺失或旧档缺来源时，相应值为空。原版命名学的预览传当前文化和语言，使用 `IsPreview` 判断预览情境。

限定范围的字段返回空时，字形盘和预制条件盘隐藏对应项目。读档和导入保留原排列。实际使用不适用的字形时跳过该排列，取反条件也不能把缺少适用范围的字段当成命中。Cultiway 独立分支用此接口读取东人服饰。人名、城市、国号、文化、语言、氏族、家族、宗教和亚种均按 Cultiway 原有十套服饰词表取词。生物排列可将「姓氏覆盖」贴在「服饰姓氏」之后，首代从服饰词库抽姓，后代采用已有姓氏。子文化沿用父文化的服饰，之后可以独立切换。亚种按出生地选取服饰和语言，仍使用世界层级的排列。

需要给某个基础预设追加条件排列时，补充包用 `cultureBases` 指定该预设，在 `arrangements` 保存新排列。排列的编辑按来源包和 ID 保存。

## 条件排列示例

在原版「命名学」选择「条件排列示例」可以加载对应类别的示例，再直接编辑它的条件、字形和词组。玩家也可以在任意命名预设下添加自己的条件排列。生物姓名可以按性别、物种和生物类别区分，城市可用建城地貌，书籍可用题材，装备可用种类、材质和命名阶段。文化、语言、宗教、家族、氏族、国家、联盟、军队、战争、格言和谋划都有各自的预制条件。

亚种、世界名和造物主名使用世界所选命名包的条件排列。亚种请求的 `kind` 表示出生地貌或分化来源。世界名和造物主名的 `kind` 是地图尺寸预设 ID，例如 `tiny` 或 `small`。在「世界信息」的全局重配入口可以把示例包应用到世界。命名包用 `arrangements` 按命名类别提供有序的条件排列，每条排列绑定原版字形短码、词组和可选的语言词库。

### 候选顺序和预设编辑

取名先尝试匹配的条件排列，再试可用的文化默认排列，随后按已解析的规则顺序逐条尝试。每条规则使用自己的原版字形排列或由部件生成的字形，再尝试该规则的结构化部件。原版字形和结构化部件各负责生成单次结果，共用同一个执行器完成重试、固定部件校验、名称限制和失败记录。主预览和实际取名采用完整候选顺序，图标提示与保存校验可以只执行正在查看的排列。史书按排列顺序提供实际事件情境，成功取名后记录采用的事件。候选耗尽后，游戏入口按既有方式回退。

`NameResult.RuleId` 和 `ArrangementId` 提供实际采用的规则和排列。`Failures` 按尝试顺序记录失败的候选，包含缺少字形、输入、词库、可用词条或结果未通过调用方约束等原因。预览沿用现有提示显示第一个失败原因及最终选中的排列或规则。

旧档原版卡片缺少可选模组的字形时，其他类别可照常加载和编辑，受影响的类别按可用规则回退。原始排列仍随存档保存。提供方重新加载后，重读同一存档即可恢复原始排列。用 `Tests/game/legacy-glyph-availability.script` 的临时副本把 `__GLYPH_TEST_MODE__` 设为 `seed` 生成旧档，重启同名环境后设为 `reopen` 验证缺字形、编辑其他类别、重新保存及恢复。

修改预设的条件排列时，世界按来源包和排列 ID 保存字形顺序、词组、条件或启用状态的修改，以及新增、删除和重排。演化排列使用提供方的变体 ID 定位。包更新后，未编辑的词组和新增排列跟随包。玩家主动排序后，新排列按基础顺序插到下一个可用的锚点之前。卸包时保留相应修改，重装同 ID 命名包后恢复。旧存档的整套覆盖和整条模板仍按原方式读入。

默认排列按命名类别、预设和规则 ID 记录改过的字形顺序和各个词组。战争、书籍、格言和装备在当前规则没有自己的编辑时，可按稳定部件 ID 复用同一预设内唯一匹配的默认编辑。未填的词组仍使用本次匹配的规则，例如史书取「纪」、兵书取「略」。子文化继承本地编辑，导出保存合并后的排列。全局重配清除原版类别的默认和条件排列编辑，同时保留语言设置。应用个人预设会替换该预设包含类别的旧编辑。

在原版为新生儿分配文化、语言和性别后，用出生时实际成功的排列确定姓氏。只保存姓氏，完整姓名等首次需要时按当前文化与语言生成。出生时所有排列都失败的情况下，保留当时的父母姓氏供后续回退。有旧姓名但没有姓氏记录的人物仍视为姓氏未知。扩展可以用 `NameRequest.WithParentSurnames` 构造出生情境。模组声明的 `FixedParts` 可绑定到原版词组或输入字形，候选无法保留固定部件时继续尝试后续排列或规则。

当前游戏进程内刷新命名包先检查文件和依赖，再更新已安装列表。已加载的文件写坏、出现同目录重复 ID，或更新引入无法满足的依赖时，提示原因并保留上次有效版本。刷新后会提示已登记类别在当前安装里缺失的字形或静态词库引用。主动关包、删除文件和删除依赖仍会影响后续取名。

`Tests/game/core-naming.script` 覆盖原版城市取名、编辑、包更新、无效刷新、重装、导出、读档、个人预设回用及全局重配。`Tests/game/city-unified.script` 和 `Tests/game/city-glyphs-reload.script` 覆盖城市切换语言、原版字形混排、实际建城和读档。`Tests/game/surname-fallback.script` 覆盖姓氏排列编辑、失败后采用父姓、换文化与语言后的首次取名和模组固定部件。跟 Cultiway 联调时，依次运行 `Tests/game/conditional-cultiway.script` 和 `Tests/game/conditional-cultiway-reload.script`，可验证条件顺序、语言取词和 Cultiway 实际建法术的结果。

服饰范围联调用 Cultiway 的 `codex/geographic-naming` 分支。把空白地图路径填入 `Tests/game/costume-scope.script` 临时副本中的 `__PLACE_HISTORY_TERRAIN__`，在同一个独立环境里运行该脚本，再重启运行 `Tests/game/costume-scope-reload.script`。脚本通过原版取名入口检查十套服饰和九类名称，再验证文化分化、语言词库、姓氏继承和读档。共享东人文化的灵猫会跳过不适用的字形和取反条件。

「世界信息 → 命名包 → 全局命名」预先计算所选范围内的名字。先算国家的新全名和简称，再用同批结果计算联盟、城市和战争，军队随后可用驻地的新地名。确认直接写入预演结果，同时写入城市地名主体和生物姓氏。若预演对象的命名输入、手改状态或命名配置发生变化，确认会要求重新预演。历史数据继续引用事件发生时的记录。`Tests/game/world-reassignment-plan.script` 覆盖预演、返回、过期检查、军队采用计划内地名、手改名、历史和读档。`Tests/game/context-scenarios.script` 覆盖模组派生字段在条件排列和实时取名中的一致性。

生效配置按命名类型、文化和语言缓存，最多保留 512 项。单个文化或语言的编辑与分化只更新相关缓存，命名包目录和全局设置变动会重建缓存。世界的包选择与各文化、语言的配置独立保存。读档兼容早期整份保存的配置，遇到无法读取的分条记录时保留原文，并继续使用旧快照里可读的同一项。全局保存保留这些原文和可读副本，正常记录继续逐条更新。全局配置本身无法读取时，独立的健康记录仍能读取和编辑。原版「命名包」页显示待恢复项，修复原记录后可重新读档。`Tests/game/profile-recovery.script` 覆盖旧档读取、损坏、重存与恢复。`Tests/game/naming-scale.script` 用 1,024 组配置和 18 代实际分化核对读档及父级关系。

## 沿革地名

在原版命名学选择「沿革地名」，可以让城市沿用迁出城市或新址所在地区的名字，让叛乱引用起事城市，也可按作者所在城市给史书取名。原版扩张时用实际迁出居民的城市，移民自己建城时用其迁出城市。每个对象保存来源及当时使用的名字，来源改名或地区重划后也能读回。原城有生成时记录的地名主体就使用主体，手改名和没有记录的旧档使用全名。

城市的历次正式名沿用原版改名记录，建城名与文化外称随同一个城市 ID 保留。「作者城市旧名」和「移民来源城旧名」字形读取建城名。旧档有原版改名记录时可用已知最早的名字。「移民来源城」仍取迁出时的名字，玩家可在排列里决定采用哪一个。新记录的迁徙与叛乱保存发生时的正式地名及当时已有的外称。

提供地理地区的模组可以在加载时调用 `GeographicNaming.RegisterRegionResolver`，从 `WorldTile` 返回 `NamingRegion`。地区由提供方加载，中文名只在建城或分化时查询当前世界。地区未准备好时返回空，原版群系和现有命名规则继续生效。Cultiway 使用主层地区名，并结合地貌、陆块和海岸识别提供建城条件。

命名包可在 `cultureVariants` 中用 `arrangement` 提供原版条件排列。可选的 `landforms` 限定分化地点。子文化只从自己使用的基础包或适用补充包新增一条排列，保留前代已采用的排列。指定过排列、卡片或规则的类别保留编辑。命名包的 `wordGroups` 也可以声明 `landforms`，让子语言优先从实际用到的词库中向当地词群调整偏好。「沿革地名」包含沿海港口、岛屿聚落、河谷渡口和山地关隘，各条排列通过原版词组和「作为词库」字形选择相应词库。

补充包可以用 `cultureBases` 把演化排列限定在已有预设，再在每条变体上用 `species` 指定可采用该变体的文化起源物种。同类、同地貌存在适用的物种变体时优先采用物种变体。「北欧沿革」随包启用后，选择「北欧风格」的灵猫文化会沿用原有预设，海岸和岛屿的演化排列用「维克」「霍尔姆」配合灵猫地名词库。父语言的手调排除和权重继续继承。

「和风沿革」与「西幻沿革」也分别提供海岸、岛屿和山地排列。和风用原有地名主体配「湊」「岛」「宿」。西幻保留通用、精灵、矮人和兽人的地名词库，各自有偏好的本地词群，例如矮人山地多用「铁脊」「岩心」配「炉堡」。原版能建城的山脚也能采用山地排列。带地区查询启动独立游戏后，`Tests/game/regional-geography.script` 使用空白地图验证三次分化、建城和读档后的原版预览。

联调使用已接入地区查询的 Cultiway，带 `--cultiway with-chinesename --history-events` 启动独立环境后运行 `Tests/game/place-history.script`。如果启动地图缺少适合建城的海岸或岛屿，可在脚本的临时副本中把 `__PLACE_HISTORY_TERRAIN__` 换成一份满足条件的空白地图路径。脚本经原版扩张、移民建城、叛乱、写书及文化和语言分化入口生成名字，并检查岛屿子文化可在原版命名学预览港口和岛屿两种排列。随后在同名环境用 `Tests/game/place-history-reload.script` 读取存档，可用共装的环境或仅加载中文名的环境检查。

## 文化外称

「中文名 · 文化外称」是可选的 NML 附属模组，位于 `Addons/CultureExonyms`。将 `ChineseName-CultureExonyms.zip` 解压到游戏的 `Mods`，与中文名并列安装。它提供通商和共居监听、外称记录、「对方国号外称」字形及「沿革地名」预设中的战争外称排列。已有名称和外称记录都随对象存档。卸载后新取名回退到本体规则，玩家保存的排列原样保留，尝试使用缺失字形时原版命名学会给出提示。

不同文化的城市在原版商船于码头完成交易时记录双方的接触。同一个文化隔至少一个游戏年再次通商，或异文化居民连续在同一城市居住满两个游戏年时，会用正式地名的已知主体和观察方的命名规则形成外称。居民的居住时间随存档保存，搬离后返城重新计时。外称按观察方文化存入相应城市或国家，形成后持续沿用。地图和对象详情继续显示正式名称。

「作者所属城市」字形在作者文化已经持有该城市外称时采用外称，并存入写书时的地名记录。「对方国号外称」字形只在战型指定的命名方已认识对方外称时有值。与「命名国」和词组可组合成战争名，「沿革地名」的普通战争已有这个条件排列。

同一个独立环境以 `Tools/game.py --culture-exonyms start` 安装附属模组，运行 `Tests/game/exonyms.script` 和 `Tests/game/resident-exonyms.script`。停止后用普通 `start` 卸载，运行 `Tests/game/exonyms-reload.script` 验证读档、提示、回退和重新保存。再次用 `--culture-exonyms start` 安装，对卸载期间保存的地图重跑读档。各个 ZIP 由 `Tools/package.py` 生成。

## 史书事件

「中文名 · 史书事件」是可选的 NML 附属模组，位于 `Addons/HistoryEvents`。将 `ChineseName-HistoryEvents.zip` 解压到游戏的 `Mods`，与中文名并列安装。它给原版书籍命名学补充事件字形、预制条件和「沿革地名」的事件排列。文化外称可以独立安装。

写史书时，作者所在国家的已结战争、叛乱与所在城市的迁徙、建城都可参与筛选。相邻的事件排列共享候选，再由条件判断可用的题材。例如城市刚发生过迁徙，「战争」排列仍可以引用更早的战争。排在前面的普通排列可以优先按城市取名。

符合条件时优先采用近期事件。同一文化近 24 次事件引用中，重复引用会下调该事件的相对优先级。同刻依次采用已结冲突、迁徙、建城。国家按类保留最近 8 场已结冲突，城市保留建城和最近 8 次迁徙。原版扩城在实际迁入后保存起终点，移民自己建城也保存来源。原版直接生成的移民记录迁入城市。旧档继续使用先前保存的事件，并可补入原版尚存的已结战争。

「沿革地名」的书籍预设通过「历史事件」字形、「有历史事件」条件和「历史事件类型」条件，分别生成《临川国与松岭邦之战始末》《澄江之乱纪略》《自澄江迁往新澄江记》《澄江建城记》。可以在原版命名学更改词组，例如把「纪略」换成「实录」。没有合适事件时用作者城市取名。书中保存实际引用的事件类型、对象 ID、发生时间和采用的称呼。建城史用建城名，安装文化外称后，迁徙和叛乱可用发生时已有的城市外称，战争史可用作者写作时已知的国号外称。

卸载后已有书名和引用继续随书存档，普通书名和沿革地名继续由本体生成。安装时加入的默认事件排列会随模组移除，原来的修改仍保存在存档中。玩家自己新建的排列继续显示，原版命名学会提示其中缺少的字形并跳过这条排列。

在同一个独立环境先用 `Tools/game.py --history-events start`，再同时加上 `--culture-exonyms`。分别运行 `Tests/game/history-events.script` 检查正式名、外称、四类事件的实际取名、预览和保存。关闭游戏重新启动时去掉 `--history-events`，运行 `Tests/game/history-events-reload.script` 检查旧书的名称和引用、新书回退与缺字形的提示。共装时也可用 `Tests/game/city-name-history.script` 验证改名、旧名取字形和迁徙发生时的外称。若起始地图缺少建城地块，可用空白地形替换脚本临时副本中的 `__PLACE_HISTORY_TERRAIN__`。

## 命名包 v1

命名包是单个 `*.naming.json`，放到游戏存档资料目录下的 `ChineseName/NamingPacks`。在「世界信息 → 命名包」点击「刷新」，再启用需要的包。基础包可独立绑定给文化和语言。包移除后，世界继续保存引用和修改，名字仍保存在原版对象上。

- `format` 固定为 `1`，`id` 使用 `作者:包名`。`version` 是从 1 开始的整数。`requires` 映射包 ID 与最低版本。
- `rules` 以类型 ID 索引规则，规则包含稳定的 `id` 和有序 `parts`。`priority` 越高越先选。`when` 检查字段值相等，`whenStartsWith` 检查文字字段的前缀，每项条件都要满足。部件使用 `pool`、`literal`、`input`、`copy` 或 `provider` 中的一种。`copy` 指向同条规则中较早的部件。
- `words` 定义稳定词条 ID、文字和基础 `weight`。`pools` 引用词条 ID 及倍率。`poolPatches` 按文件顺序追加、替换或排除，包之间使用优先级。同词条重复包含时取最高倍率。语言偏好和排除在包合并后生效。
- 补充包可以用 `fallbackPools` 提供默认词库。已选语言基础包包含同 ID 词库时，使用该基础包的词表，避免重新加入导出时已排除的词。词库别名和词群仍可引用。
- `poolAliases` 把原版词组里可填写的单个名称指向词库 ID，例如 `"poolAliases": { "江河地名": "chinesename:river-places" }`。在命名学把「作为词库」放到该组右边，取名时先抽一个名称，再按当前语言从对应词库取词。同一名称指向多个词库时，用 `chinesename/river-places` 这种写法指向明确的词库。斜杠用来避开原版剪贴板格式里的冒号。
- `poolRenames` 把旧的完整词库 ID 指向当前 ID。已有旧 ID 时优先使用现有词库。迁移保留语言的权重、排除项和词群偏好，词群要保留原有 ID，并把 `pool` 改为新 ID。多个旧设置指向同一目标时，优先使用目标已有的设置，无法唯一选择的修改继续保留。命名学里的显示别名继续由 `poolAliases` 定义。
- `partRenames` 按命名类型列出本包的旧部件 ID 和新部件 ID，例如 `{"worldbox:city":{"old-root":"name"}}`。默认与条件排列的原版词组通过 `roles` 绑定稳定部件 ID，移动槽位后继续应用玩家修改。无法解析的绑定保留原文，并在刷新「命名包」时提示。先前没有记录部件 ID 的槽位编辑沿用原来的槽位含义。`Tests/game/pack-id-upgrade.script` 覆盖原版编辑、缺少迁移声明、恢复、实际取名和读档。
- `supplemental` 表示补充包。`cultureBases` 和 `languageBases` 可限定补充内容作用的基础包。`ruleEdits` 按 `类型ID/规则ID` 定位局部修改，可独立设置继承、部件顺序和部件字段。`parts` 用于添加或整体替换部件，`fields` 用于局部编辑。`languageEdits` 按词库 ID 设置词条偏好与排除。
- `cultureVariants` 按包内 ID 声明文化分化时可选的改动。每项指定 `type`、`rule` 与 `part`，并在 `literal` 和 `chance` 中提供一项。分化只改变原有固定文字或可选部件的抽取概率，避开姓氏和玩家已固定的字段。
- `wordGroups` 按包内 ID 声明词群。每项指定 `pool` 及词条 ID 列表 `words`。子语言继承父语言的偏好与手调设置，每次只把一个可分化词库的 20% 自动偏好移向一个词群。优先选择当前文化生效的排列和规则可引用的词库，手动限制的词库跳过分化。
- 补充包的 `languageEdits` 可用 `group` 限定词群，引用格式为 `包ID/词群ID`。玩家给语言设置的限定词群优先于补充包默认值。独立基础包导出会携带已导出词表对应的词库别名和词群，词群保留词表里仍可用的成员。
- 文化命名学的「命名包 → 导出」把文化已编辑的原版排列写入对应规则的 `nativeCards`，保留词组、字形、绑定和继承方式。词库使用导出时所选语言的有效词表和权重。带排列的独立包设有 `useAsLanguageDefault`，在文化选用此包且语言没有指定其他基础包时提供词库。导入后可在目标文化的原版命名学里继续编辑。
- 个人预设在命名学保存和应用，在游戏设置的「我的预设」导入导出。玩家库位于 `ChineseName/Presets`，分享文件位于 `ChineseName/PresetExports`。预设携带基础词库，目标世界的语言偏好由当地重新计算。世界只保存本世界文化使用的预设副本。
- 默认包和「西式本地化」命名集用 `python3 Tools/default_pack.py` 一起生成。西式命名集可以独立安装和启用。人物规则支持姓在后、中文间隔号和原文空格，内置词库提供英式和法式词群。
- 内置物种风格与可选物种命名集使用同一份 `ChineseNamePackages/species_styles.toml`，由 `python3 Tools/variant_packs.py` 生成。内置规则跟随「华语地名与人名」文化基础包，只匹配已登记的物种，普通人族继续用华语规则。词库随模组加载，可在其他风格和语言中引用。
- 国风、和风和西幻的命名集由 `python3 Tools/variant_packs.py` 生成，引用独立词库包。规则的 `useNativeWordGroups` 可把必选部件里的直接词库和单词常量展开为原版词组。直接词库会跟一枚「作为词库」，优先填写可唯一解析的词库名，存在重名时填写带来源的词库 ID。结构和词群查询共用命名学的原版执行路径。
- 三套命名集各提供 13 类。「文化起源物种」统一用于西幻的各个分类。`useNativeWordGroups` 也会把能匹配已有专属字形的必选输入部件放进原版排列。`fallbackPool` 用于输入缺失，或输入映射的词库没有可用词时，按该语言从指定词库补词。原版字形、预览与无原版上下文的生成路径使用同一回退规则。

旧版整模组的语料可以转换成单个补充包。工具读取 ZIP 或目录里的默认词表和指定风格的模板。例如：

```sh
python3 Tools/import_legacy_pack.py old.zip old.naming.json --id myname:old-style --style default
```

每个旧生成器保留一个可转换的排列，优先取旧权重较高的支持项。转换支持普通词表、固定文字、姓氏标记和少量等义的请求字段。旧代码、动态模板和复杂权重组合需要按转换报告整理。把输出放进现有「命名包」页显示的目录即可扫描启用。

最小包可参考 [法术默认包](../../Examples/SpellNames/Content/spell.naming.json)，API 用法见 [示例模组](../../Examples/SpellNames/Source/SpellNames.cs)。游戏将世界配置写入 `MapStats.custom_data`，把完整姓氏和已生成的名写到 `ActorData`，已有显示名称由原版保存。

## 构建和复测

在项目根目录执行下列命令。可用 `-p:GameRootPath=/path/to/worldbox` 指定游戏目录，编译应使用该安装中 NML 公开化的 `Assembly-CSharp`。

```sh
dotnet build --nologo
dotnet run --project Tests/Core/Core.csproj
python3 Tools/default_pack.py --check
```

`Tools/game.py` 使用同级 Cultiway `develop` 的游戏复制与 DebugToolbox 会话流程，缺少同级目录时可指定 `--reference`。`setup` 在 `~/.local/state/chinesename-dev` 创建独立环境，`start` 冻结当前发布输入，确认 Unity 进程、资料目录与实际加载的模组。用下面的命令在其内验证。验证脚本和结果按运行保留在 `runs/*/cases/`。

```sh
python3 Tools/game.py setup
python3 Tools/game.py --spell-example start
python3 Tools/game.py run Tests/game/spell.script
python3 Tools/game.py run Tests/game/person.script
python3 Tools/game.py stop
python3 Tools/game.py --spell-example start
python3 Tools/game.py run Tests/game/reload.script
python3 Tools/game.py run Tests/game/lifecycle.script
python3 Tools/game.py run Tests/game/packages.script
python3 Tools/game.py run Tests/game/entrypoints.script
python3 Tools/game.py run Tests/game/species.script
python3 Tools/game.py run Tests/game/editor.script
python3 Tools/game.py stop
```

用 `python3 Tools/package.py` 生成发行压缩包。`ChineseName.zip` 包含本体和全部随附命名包，额外的包依然可以通过单个 JSON 分享。文化外称和史书事件分别打成 `ChineseName-CultureExonyms.zip` 和 `ChineseName-HistoryEvents.zip`，可以各自与 2.4.0 起的本体并列安装。「新支系开姓」打成 `ChineseName-SurnameBranches.zip`，需要 2.5.0 或更新的本体。独立法术示例可以从仓库的 `Examples/SpellNames` 获取。

「新支系开姓」在文化分化或移民建城后，以八分之一的概率留一次开姓机会。符合条件的人在出生或首次取名时，沿用原版命名学当前排列引用的姓氏词库，以及自己语言的权重和排除项。选姓先排除父母的姓，再优先取世界上尚无人使用的姓，全部有人用时取使用人数最少的候选。机会随文化或城市存档，姓氏、家族名和继承仍由本体处理。用独立实例的 `--surname-branches` 选项运行 `Tests/game/surname-branches.script`，重启后运行 `Tests/game/surname-branches-reload.script`。第二次重启可省略附属模组选项，验证卸载后的读档和取名。

命名学验证使用 `python3 Tools/game.py --name onomastics start` 启动独立实例。运行 `Tests/game/society-onomastics.script` 核对国家等类别在原版命名学的编辑和真实取名，再执行 `stop`、`start`，用同名实例运行 `Tests/game/society-onomastics-reload.script`。脚本保存和重新打开 `.wbox`，核对已有名字、原版排列和之后生成的新名字。

战争等扩展类别的验证脚本为 `Tests/game/culture-extended-naming.script` 和 `Tests/game/culture-extended-naming-reload.script`。前者检查分类容器换行，对照两个文化并触发实际取名，后者重启后核对字形、文化分化和重置。

联调 Cultiway 的法术字形盘时，在加载两者的独立环境里依次运行 `Tests/game/cultiway-onomastics.script` 和 `Tests/game/cultiway-onomastics-reload.script`。测试使用同一实际火球构建入口核对文化排列、语言抽词和读档。

专属字形联调先运行 `Tools/verify-glyphs.py Tests/game/context-glyphs.script`，为它提供隔离显示器、环境名和 `--cultiway with-chinesename`。用同一环境重启后运行 `Tests/game/context-glyphs-reload.script`，核对装备、法术和社会对象的排列与取名。命名集用 `Tests/game/naming-sets.script` 生成单独存档，重启并运行 `Tests/game/naming-sets-reload.script`，核对卸包后的回退和重装后的恢复。

社区包转换后，可在临时副本中把 `Tests/game/legacy-packs.script` 的 `__LEGACY_PACKS__` 替换成转换产物的绝对目录，再由独立游戏运行。该场景检查命名包安装、取名，以及多个包的同名词库如何用明确 ID 区分。

个人预设用整合版在第一份隔离玩家资料运行 `Tools/verify-glyphs.py Tests/game/player-presets.script`。将返回的 `output` 路径填入 `Tests/game/player-presets-import.script` 的 `__PRESET_TRANSFER__`，再用空白的第二份隔离玩家资料运行。两个场景分别检查跨存档选用、语言独立取词，以及分享文件的导入去重和脱离源资料读档。

用同一个分享输出填入 `Tests/game/manage-player-presets.script` 的 `__PRESET_TRANSFER__`，在空白隔离资料中通过 `Tools/verify-glyphs.py` 实点重命名和删除。重启该环境，再运行 `Tests/game/manage-player-presets-reload.script` 核对玩家库和存档副本。

全局重配用整合版运行 `Tools/verify-glyphs.py Tests/game/world-reassignment.script`。鼠标在「世界信息 → 命名包 → 全局命名」中选用预设，核对取消、仅重配规则和同时重取名字。用同名环境重启后运行 `Tests/game/world-reassignment-reload.script`，分别读回预置开场地图和旧档，随后核对谋划的文化排列、语言取词及特殊事件命名。

统一字形盘的验证使用独立的 `parts-editor` 环境和 Xvfb。将 `Tools/verify-glyphs.py --display <隔离显示器>` 分别指向 `Tests/game/city-glyphs.script` 和 `Tests/game/parts-editor.script`，用系统鼠标点击字形、从原版词组输入文字并拖动排列，检查只读预览。两个场景各从新地图开始。保存后用同名环境运行 `city-glyphs-reload.script` 和 `parts-editor-reload.script`。读档检查已生成的名字、原版排列和后续取名。打开城市命名学后，用同一工具运行 `Tests/game/parts-editor-keyboard.script`，通过实际 Tab 和 Shift+Tab 检查焦点切换，并验证提交与取消。

## 当前验收范围

`Tests/game/conditional-categories.script` 检查 18 个原版命名类别的条件样例、15 个可在文化命名学编辑的类别，以及沿用的 29 对字形 ID 和短码。`Tests/game/society-onomastics.script` 和 `Tests/game/culture-extended-naming.script` 及各自的读档脚本核对编辑、预览、实际生成和读档重开。`Tests/game/entrypoints.script` 另检查世界名、造物主名、亚种和船只条件的读档。世界名、造物主名和亚种沿用世界命名规则，船只在生物分类编辑。
