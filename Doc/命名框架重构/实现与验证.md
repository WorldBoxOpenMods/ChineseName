# 命名框架实现与验证

这里记录当前代码的接口和验证方式。[分阶段计划](分阶段重构计划.md)和[设计讨论](设计讨论.md)保留产品行为及历史方案。草案中的 JSON 示例不作为 v1 格式使用。

文化档案「命名学」把生物、城市、国家、家族、氏族、文化、语言、宗教、战争、联盟、军队、书籍、格言、装备和模组类别放在同一个分类容器，按宽度自动换行。各类别共用原版词组、字形、只读预览和语言对照。原版已有命名学数据的类别把卡片保存在原版文化数据里，其余类别保存在同一地图的模组文化设置里。文化分化继承这些设置。未填写的词组可按本次取名匹配的规则继续取词，比如史书与兵书保留各自的后缀。亚种、世界和造物主使用世界级命名规则。

战争用战型指定的一方国家作为文化来源，联盟用发起国，军队优先用驻地城市，书籍用作者。格言沿用其国家、氏族或联盟的文化来源；氏族还未产生首领时可沿用创始人的文化。传奇装备和重铸优先用制作者的文化，缺少制作者时取出产国的文化。这些规则用于实际生成或重铸时，已有名称和自定义名称按原版行为保存。

## 其他模组接入

在模组清单的 `Dependencies` 中加入 `CHINESENAME`，在 `OnModLoad` 通过 `NamingApi.Current.RegisterType` 注册带命名空间的稳定 ID、界面名称及输入字段。模组如果自带默认规则，可以使用第二个参数注册一个自动启用的补充包。调用方负责把角色、功法、法术等领域对象转换成 `NameRequest`，以及在 `Success` 为真时存储 `Text`。失败时可读 `Status` 和 `Diagnostics`，并使用调用方现有的回退。游戏里的调用应在主线程执行。

```csharp
var request = new NameRequest(
    "spell-example:spell", seed: 42, culture: cultureId, language: languageId,
    inputs: new Dictionary<string, object> { ["element"] = "fire", ["form"] = "blade" });
var result = NamingApi.Current.Generate(request);
if (result.Success) SaveName(result.Text);
```

`Preview` 接收同样的请求及可选的世界草稿。结果的 `Parts` 按稳定部件 ID 提供组成文字。命名不会设置游戏对象的名称。候选提供者通过 `RegisterProvider` 注册，每次请求至多读取一次，最多接收 128 个候选；提供者应稳定且无副作用。`Text`、`Integer`、`Flag` 是当前可声明的输入类型，原版和模组类型从同一注册表进入编辑窗口。

Cultiway 以可选依赖接入。共享法术使用世界级规则，有明确创法者的构建使用其文化和语言。法术词素从 Cultiway 已有的元素、形态、运动和词条资源转换成中文名词库。Cultiway 保留原规则回退及后续 AI 命名流程。东方人族通过 `RegisterDefaultPack` 提交种族规则，人物、城市、国家、文化和语言都走框架已有的入口。新增种族也可以复用这个做法，无需登记一个新的人物命名类型。

输入字段可以提供 `example`，让编辑器第一次预览就有有效输入。词库部件可以声明 `poolInput`，将已声明的文本字段作为池编号后缀。例如 `pool: "cultiway:spell-element"` 和 `poolInput: "element"` 会用输入 `semantic.element.fire` 选择 `cultiway:spell-element.semantic.element.fire`。这些词库仍能在语言页调整。

如需在原版「命名学」展示类别，登记命名类型后调用 `RegisterCultureOnomastics(typeId, icon, description)`。后两项可省略，`icon` 使用游戏资源路径。分类按钮与原版其他类别共用同一个字形盘，使用输入字段的 `example` 预览。默认规则的词库、固定文字、输入和候选列表可以投影为词组，词组留空时继续按实际请求取词。直接调用候选提供者、复制其他部件或传入固定部件的规则仍可通过结构化规则生成。Cultiway 的「修仙法术」用火球作预览示例，实际取词仍由法术的语义和创法者的语言决定。

Cultiway 的默认法术排列中，词组 I 到 IV 依次使用元素、主要词条、运动和形态。可以在新词组写入「诀」，只排列元素词组与这个新词组。元素词组留空，同一种火球即可随语言取成「炎诀」或「火诀」。

类别注册后也可以在模组加载时调用 `RegisterCultureGlyph`。下面的字形按实际法术元素选择词库。输入为 `semantic.element.fire` 时，按当前语言从 `cultiway:spell-element.semantic.element.fire` 抽词。

```csharp
service.RegisterCultureGlyph("cultiway:spell", "cultiway:spell-element", '\uE240',
    "element", "法术元素", "ui/Icons/iconFire", poolPrefix: "cultiway:spell-element");
```

字形用带命名空间的 ID 和发布后固定的私用区短码，重复的 ID 或短码会报错。省略 `poolPrefix` 时直接使用请求输入。给前缀加尾连字符可引用历史词库 ID，例如 `chinesename:book-` 和题材 `history` 组合成 `chinesename:book-history`。可以另指定 `fallbackPool`，在输入或对应词库缺失时从中取词。

战争请求的 `kind` 是原版战争类型 ID，`attacker` 和 `defender` 是宣战时双方的国名，`origin` 及文化和语言取自该战争类型指定的命名方。例如 `normal` 以进攻国为来源，`rebellion` 以防守国为来源。默认规则按类型选择称谓，补充包可以把双方国名放在同一条规则里。书籍请求的 `kind` 是原版书名模板 ID，例如 `book_name_history`。

## 命名包 v1

命名包是单个 `*.naming.json`，放到游戏存档资料目录下的 `ChineseName/NamingPacks`。在「世界信息 → 命名包」点击「刷新」，再启用需要的包。基础包可独立绑定给文化和语言。包移除后，世界继续保存引用和修改，名字仍保存在原版对象上。

- `format` 固定为 `1`，`id` 使用 `作者:包名`。`version` 是从 1 开始的整数。`requires` 映射包 ID 与最低版本。
- `rules` 以类型 ID 索引规则，规则包含稳定的 `id` 和有序 `parts`。`priority` 越高越先选。`when` 检查字段值相等，`whenStartsWith` 检查文字字段的前缀，每项条件都要满足。部件使用 `pool`、`literal`、`input`、`copy` 或 `provider` 中的一种。`copy` 指向同条规则中较早的部件。
- `words` 定义稳定词条 ID、文字和基础 `weight`。`pools` 引用词条 ID 及倍率。`poolPatches` 按文件顺序追加、替换或排除，包之间使用优先级。同词条重复包含时取最高倍率。语言偏好和排除在包合并后生效。
- 补充包可以用 `fallbackPools` 提供默认词库。已选语言基础包包含同 ID 词库时，使用该基础包的词表，避免重新加入导出时已排除的词。词库别名和词群仍可引用。
- `poolAliases` 把原版词组里可填写的单个名称指向词库 ID，例如 `"poolAliases": { "江河地名": "chinesename:river-places" }`。在命名学把「作为词库」放到该组右边，取名时先抽一个名称，再按当前语言从对应词库取词。同一名称指向多个词库时，用 `chinesename/river-places` 这种写法指向明确的词库。斜杠用来避开原版剪贴板格式里的冒号。
- `supplemental` 表示补充包。`cultureBases` 和 `languageBases` 可限定补充内容作用的基础包。`ruleEdits` 按 `类型ID/规则ID` 定位局部修改，可独立设置继承、部件顺序和部件字段。`parts` 用于添加或整体替换部件，`fields` 用于局部编辑。`languageEdits` 按词库 ID 设置词条偏好与排除。
- `cultureVariants` 按包内 ID 声明文化分化时可选的改动。每项指定 `type`、`rule` 与 `part`，并在 `literal` 和 `chance` 中提供一项。分化只改变原有固定文字或可选部件的抽取概率，避开姓氏和玩家已固定的字段。
- `wordGroups` 按包内 ID 声明词群。每项指定 `pool` 及词条 ID 列表 `words`。子语言继承父语言的偏好与手调设置，每次只把一个可分化词库的 20% 自动偏好移向一个词群。优先选择当前文化生效的排列和规则可引用的词库，手动限制的词库跳过分化。
- 补充包的 `languageEdits` 可用 `group` 限定词群，引用格式为 `包ID/词群ID`。玩家给语言设置的限定词群优先于补充包默认值。独立基础包导出会携带已导出词表对应的词库别名和词群，词群保留词表里仍可用的成员。
- 文化命名学的「命名包 → 导出」把文化已编辑的原版排列写入对应规则的 `nativeCards`，保留词组、字形、绑定和继承方式。词库使用导出时所选语言的有效词表和权重。带排列的独立包设有 `useAsLanguageDefault`，在文化选用此包且语言没有指定其他基础包时提供词库。导入后可在目标文化的原版命名学里继续编辑。
- 个人预设在命名学保存和应用，在游戏设置的「我的预设」导入导出。玩家库位于 `ChineseName/Presets`，分享文件位于 `ChineseName/PresetExports`。预设携带基础词库，目标世界的语言偏好由当地重新计算。世界只保存本世界文化使用的预设副本。
- 默认包和「西式本地化」命名集用 `python3 Tools/default_pack.py` 一起生成。西式命名集可以独立安装和启用。人物规则支持姓在后、中文间隔号和原文空格，内置词库提供英式和法式词群。
- 内置物种风格与可选物种命名集使用同一份 `ChineseNamePackages/species_styles.toml`，由 `python3 Tools/variant_packs.py` 生成。内置规则跟随「华语地名与人名」文化基础包，只匹配已登记的物种，普通人族继续用华语规则。词库随模组加载，可在其他风格和语言中引用。
- 国风、和风和西幻的命名集由 `python3 Tools/variant_packs.py` 生成，引用独立词库包。规则的 `useNativeWordGroups` 可把必选部件里的直接词库和单词常量展开为原版词组。直接词库会跟一枚「作为词库」，优先填写可唯一解析的词库名，存在重名时填写带来源的词库 ID。结构和词群查询共用命名学的原版执行路径。
- 三套命名集各提供 13 类。「文化起源物种」统一用于西幻的各个分类。`useNativeWordGroups` 也会把能匹配已有专属字形的必选输入部件放进原版排列。`fallbackPool` 用于输入缺失，或输入映射的词库没有可用词时，按该语言从指定词库补词。原版字形、预览与无原版上下文的生成路径使用同一回退规则。

旧版整模组的语料可以转换成单个补充包。工具读取 ZIP 或目录里的默认词表和指定风格的模板。例如：

```sh
python3 Tools/import_legacy_pack.py old.zip old.naming.json --id myname:old-style --style default
```

每个旧生成器保留一个可转换的排列，优先取旧权重较高的支持项。转换支持普通词表、固定文字、姓氏标记和少量等义的请求字段。旧代码、动态模板和复杂权重组合需要按转换报告整理。把输出放进现有「命名包」页显示的目录即可扫描启用。

最小包可参考 [法术默认包](../../Examples/SpellNames/Content/spell.naming.json)，API 用法见 [示例模组](../../Examples/SpellNames/Source/SpellNames.cs)。游戏将世界配置写入 `MapStats.custom_data`，把完整姓氏和已生成的名写到 `ActorData`，已有显示名称由原版保存。

## 构建和复测

在项目根目录执行下列命令。可用 `-p:GameRootPath=/path/to/worldbox` 指定游戏目录，编译应使用该安装中 NML 公开化的 `Assembly-CSharp`。

```sh
dotnet build --nologo
dotnet run --project Tests/Core/Core.csproj
python3 Tools/default_pack.py --check
```

`Tools/game.py` 使用同级 Cultiway `develop` 的游戏复制与 DebugToolbox 会话流程，缺少同级目录时可指定 `--reference`。`setup` 在 `~/.local/state/chinesename-dev` 创建独立环境，`start` 冻结当前发布输入，确认 Unity 进程、资料目录与实际加载的模组。用下面的命令在其内验证。验证脚本和结果按运行保留在 `runs/*/cases/`。

```sh
python3 Tools/game.py setup
python3 Tools/game.py --spell-example start
python3 Tools/game.py run Tests/game/spell.script
python3 Tools/game.py run Tests/game/person.script
python3 Tools/game.py stop
python3 Tools/game.py --spell-example start
python3 Tools/game.py run Tests/game/reload.script
python3 Tools/game.py run Tests/game/lifecycle.script
python3 Tools/game.py run Tests/game/packages.script
python3 Tools/game.py run Tests/game/entrypoints.script
python3 Tools/game.py run Tests/game/species.script
python3 Tools/game.py run Tests/game/editor.script
python3 Tools/game.py stop
```

用 `python3 Tools/package.py` 生成 `ChineseName.zip`。压缩包含模组和全部随附命名包，额外的包依然可以通过单个 JSON 分享。独立法术示例可以从仓库的 `Examples/SpellNames` 获取。

命名学验证使用 `python3 Tools/game.py --name onomastics start` 启动独立实例。运行 `Tests/game/society-onomastics.script` 核对国家等类别在原版命名学的编辑和真实取名，再执行 `stop`、`start`，用同名实例运行 `Tests/game/society-onomastics-reload.script`。脚本保存和重新打开 `.wbox`，核对已有名字、原版排列和之后生成的新名字。

战争等扩展类别的验证脚本为 `Tests/game/culture-extended-naming.script` 和 `Tests/game/culture-extended-naming-reload.script`。前者检查分类容器换行，对照两个文化并触发实际取名，后者重启后核对字形、文化分化和重置。

联调 Cultiway 的法术字形盘时，在加载两者的独立环境里依次运行 `Tests/game/cultiway-onomastics.script` 和 `Tests/game/cultiway-onomastics-reload.script`。测试使用同一实际火球构建入口核对文化排列、语言抽词和读档。

专属字形联调先运行 `Tools/verify-glyphs.py Tests/game/context-glyphs.script`，为它提供隔离显示器、环境名和 `--cultiway with-chinesename`。用同一环境重启后运行 `Tests/game/context-glyphs-reload.script`，核对装备、法术和社会对象的排列与取名。命名集用 `Tests/game/naming-sets.script` 生成单独存档，重启并运行 `Tests/game/naming-sets-reload.script`，核对卸包后的回退和重装后的恢复。

社区包转换后，可在临时副本中把 `Tests/game/legacy-packs.script` 的 `__LEGACY_PACKS__` 替换成转换产物的绝对目录，再由独立游戏运行。该场景检查命名包安装、取名，以及多个包的同名词库如何用明确 ID 区分。

个人预设用整合版在第一份隔离玩家资料运行 `Tools/verify-glyphs.py Tests/game/player-presets.script`。将返回的 `output` 路径填入 `Tests/game/player-presets-import.script` 的 `__PRESET_TRANSFER__`，再用空白的第二份隔离玩家资料运行。两个场景分别检查跨存档选用、语言独立取词，以及分享文件的导入去重和脱离源资料读档。

用同一个分享输出填入 `Tests/game/manage-player-presets.script` 的 `__PRESET_TRANSFER__`，在空白隔离资料中通过 `Tools/verify-glyphs.py` 实点重命名和删除。重启该环境，再运行 `Tests/game/manage-player-presets-reload.script` 核对玩家库和存档副本。

统一字形盘的验证使用独立的 `parts-editor` 环境和 Xvfb。将 `Tools/verify-glyphs.py --display <隔离显示器>` 分别指向 `Tests/game/city-glyphs.script` 和 `Tests/game/parts-editor.script`，用系统鼠标点击字形、从原版词组输入文字并拖动排列，检查只读预览。两个场景各从新地图开始。保存后用同名环境运行 `city-glyphs-reload.script` 和 `parts-editor-reload.script`。读档检查已生成的名字、原版排列和后续取名。打开城市命名学后，用同一工具运行 `Tests/game/parts-editor-keyboard.script`，通过实际 Tab 和 Shift+Tab 检查焦点切换，并验证提交与取消。

## 当前验收范围

独立游戏使用 Linux WorldBox 0.51.2 与当前安装中的 NML。只加载中文名、DebugToolbox 和测试时指定的法术示例。Unity 用户资料、游戏日志、脚本、会话和测试存档均位于中文名的独立运行根目录。

| 场景 | 已取得的验证结果 |
| --- | --- |
| 首次命名、出生与保存 | 两个孩子继承完整「欧阳」。应用新包后，延迟取名的孩子获得「欧阳澄川」，父亲保留已有姓名。关闭游戏再加载 `.wbox` 存档恢复姓名、姓氏和包选择。 |
| 原版自动命名入口 | 触发城市、国家、文化、语言、宗教、家族、氏族、联盟、战争、三类格言、书籍、军队、亚种及装备重铸。世界生成使用中文世界名。手改军队和装备名保留。 |
| 生命周期 | 游戏中实际创建克隆、僵尸和骷髅，核对其姓名和完整姓氏。 |
| 扩展 | 通过 NML 加载独立法术示例。注册类型可发现，生成与预览都得到「炎刃诀」。 |
| 命名包装卸 | 导出 JSON、扫描安装、预览、启用、删除、再安装；其他世界使用自己的配置。 |
