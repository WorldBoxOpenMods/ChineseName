# 原版命名入口与覆盖清单

核对日期：2026-10-23。

本文依据 `../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/` 中的反编译源码，记录自动命名入口、触发时机和可用信息，供框架设计与后续验收使用。产品行为以[设计讨论](设计讨论.md)为准，数据组织见[规则与数据模型草案](规则与数据模型草案.md)，入口见[讨论总览](../命名框架重构-摘要.md)。

本页记录实施前的静态核对。2026-11-18 的实现状态和游戏内复测方法见[实现与验证](实现与验证.md)。下文关于待验收的表述保留为原始验收任务。

## 通用路径

原版主体路径为 `Actor.generateName` → `NameGenerator.generateName` → 文化命名学或默认命名资源。个人姓名由 `Actor.generateNewName` 直接调用 `NameGenerator.generateName`。

[NameGenerator.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/NameGenerator.cs) 中有两点会影响接入：

- 对象有文化时优先取该文化的命名学；对象没有文化时，还会查找亲代文化，再使用物种命名资源。这是原版行为，需要与新框架已经确认的默认方案选择分别处理，不能直接当成新框架的继承规则。
- `generateNameFromTemplate` 内部仍会优先分派给命名学，除非显式强制旧模板。因此，命名方法名称不足以判断实际执行路径。

[NameSetAsset.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/NameSetAsset.cs) 的类型映射只覆盖个人、城市、国家、文化、语言、宗教、家族、氏族八类。[MetaType.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/MetaType.cs) 的枚举更广，但枚举中存在某类型，不代表原版已经为它提供了可编辑的命名学。

## 经过主体命名路径的对象

表中“可用信息”指接入处可以提取的对象信息，不代表通用生成器的现有参数已经传入全部信息。

| 对象 | 已核对入口与时机 | 可用信息与接入要求 |
| --- | --- | --- |
| 生物个体 | [Actor.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/Actor.cs)：`getName` 发现名字为空时调用 `generateNewName`，使用 `MetaType.Unit`。 | 生物、物种、亚种、性别、当前文化与语言、亲代、所属城市和国家等。姓氏需要独立的出生与继承处理，不能只等首次读取名字。 |
| 城市 | [City.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/City.cs)：`newCityEvent` → `generateName`。 | 创建者及城市信息；调用创建者的 `generateName(MetaType.City, ...)`。 |
| 国家 | [Kingdom.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/Kingdom.cs)：`newCivKingdom`。 | 创建者及新国家信息；使用 `MetaType.Kingdom`。 |
| 文化 | [Culture.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/Culture.cs)：`createCulture`。 | 创建者及其原有文化、语言和物种；新文化自身的配置尚处于初始化过程。 |
| 语言 | [Language.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/Language.cs)：`newLanguage` → `generateName`。 | 创建者及其已有文化、语言和物种；新语言的词库偏好不能成为它自身初始化的循环依赖。 |
| 宗教 | [Religion.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/Religion.cs)：`newReligion` → `generateName`。 | 创建者、创建地点和宗教信息；使用 `MetaType.Religion`。 |
| 家族 | [Family.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/Family.cs)：`newFamily` → `generateName`。 | 一位或两位创建者、物种、起源城市等；使用 `MetaType.Family`。家族对象的名字与个人继承的姓氏需要分别表示。 |
| 氏族 | [Clan.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/Clan.cs)：`newClan`。 | 创建者、文化、语言、物种和氏族信息；使用 `MetaType.Clan`。 |

四大种族之外的动物、怪物和特殊生物仍需沿个人命名路径检查默认内容。[ActorAssetLibrary.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/ActorAssetLibrary.cs) 包含大量物种命名集绑定，以及 UFO、蚂蚁等单独的个人命名资源绑定；[ActorAsset.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/ActorAsset.cs) 的 `getNameTemplate` 决定资源回退。

船只在原版中也使用 Actor 体系，资源定义包含 `is_boat`。[CityBehProduceBoat.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/ai/behaviours/CityBehProduceBoat.cs) 会让造出的船加入城市和国家。接入与内容验收需要单独检查船只条件，避免沿默认个人规则生成普通人的姓名。已确认船只优先采用所属城市的文化与语言，缺少时采用所属国家，再缺少则使用适用的世界默认方案。

| 书名 | [Book.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/Book.cs)：`newBook`。 | 由书籍类型选择模板，传入作者。完整入口还提供书籍主题相关的特质参数；实际语言信息来自作者。 |

| 氏族格言 | [Clan.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/Clan.cs)：`getMotto` 在格言为空时生成。 | 调用 `getName("clan_mottos")`，需要补充氏族及可用的文化、语言信息。 |
| 联盟格言 | [Alliance.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/Alliance.cs)：`getMotto` 在格言为空时生成。 | 调用 `getName("alliance_mottos")`，需要明确多国对象采用哪一方的文化与语言。 |
| 世界名 | [MapStats.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/MapStats.cs)：`initNewWorld`。 | 调用 `getName("world_name")`。新世界初始化阶段可能没有文化或语言对象，应使用世界默认配置。 |

## 名字的衍生、复制与直接写入

以下路径不能通过接管 NameGenerator 自动覆盖。它们也不能直接等同于“为一个全新对象随机取名”。

| 场景 | 源码事实 | 需要处理的边界 |
| --- | --- | --- |
| 僵尸与骷髅转换 | [ActionLibrary.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/ActionLibrary.cs)：`turnIntoZombie`、`turnIntoSkeleton` 复制原对象信息，再按条件添加 `Un` 前缀。 | 已确认保留原姓名与姓氏；需要在接入时处理原版后续写名，保证既有命名状态得到保留。 |
| 骷髅亚种 | [Subspecies.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/Subspecies.cs)：`setSkeletonForm` 使用配置前缀与原亚种名组合。 | 作为亚种衍生命名入口记录，保留原亚种信息，不能只改首次生成入口。 |
| 亚种升格 | [ActorManager.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/ActorManager.cs)：`evolutionEvent` 在升格分支给亚种名追加 `Ascentus`。 | 已确认保留个人姓名，产生新亚种时单独为其命名；亚种后缀路径仍需适配，具体规则形式待定。 |
| 克隆 | [ActorManager.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/ActorManager.cs)：`cloneUnit` 复制名字和 `custom_name`。[ActorTool.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/ai/ActorTool.cs) 的复制流程逐项复制指定字段。 | 已确认复制原姓名、姓氏与组成部分；需要显式核对框架状态的复制，不能假设自定义字段会自动随名字复制。 |
| 文化分化 | [Culture.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/Culture.cs)：`cloneAndEvolveOnomastics` 复制原文化规则并执行 scramble。 | 新框架已确认的文化继承与独立编辑行为需要在这里衔接，避免原版演化逻辑继续改写新配置。 |
| 预设名字 | [MapBox.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/MapBox.cs) 的启动世界分支直接给角落单位赋予固定名字；[Actor.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/Actor.cs) 也可在创建文化后采用外部传入的文化名。 | 这些是已有名字的直接赋值路径，需要区分预设与自动生成；不应统一拦截所有 `setName` 并强制重取。 |
| 玩家手改 | [UnitWindow.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/UnitWindow.cs)、[WindowMetaGeneric.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/WindowMetaGeneric.cs) 写名字前设置 `custom_name`；[WorldWindow.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/WorldWindow.cs) 直接修改世界名。 | 命名包切换与编辑应用不应覆盖玩家名字；不同对象的手改标记不能假设完全一致。 |

## 姓氏接入时序

[BabyMaker.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/BabyMaker.cs) 的 `makeBaby` 创建孩子后设置亲代关系，再由 [BabyHelper.cs](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/BabyHelper.cs) 的 `applyParentsMeta` 确定亚种、文化与语言等信息。生物姓名的首次生成则可能发生在后面的 `getName` 调用。

按已确认的行为，出生文化决定从哪位亲代完整继承姓氏，语言或文化后续变化不重取这个姓。因此，出生接入需要在文化与亲代关系可用时完成继承选择，并保存已确定的姓氏。不能等以后第一次显示名字时，再用当时的文化重新判断。

姓名的生成仍读取已确定的姓氏，并为新取的名选择词库。亲代尚未取姓时，应先确定并保存其姓氏；预览使用输入副本，不能执行这类世界写入。

具体接入位置还需要验证：出生流程内部创建家族时可能读取亲代名字，其他补丁也可能提前读取孩子名字。因此，只给某个方法添加 Postfix 并不能直接证明时序正确。首次读取、出生初始化和读档恢复应共同遵守“已有确定姓氏就复用”的约束。

## 接下来建议确定的模块边界

这份清单支持先确定下列职责，再定具体类和公开接口；当前为架构建议。

| 模块 | 职责 |
| --- | --- |
| 游戏接入 | 识别触发场景，取得创建者、所有者、双方国家、物种和亲代等信息，完成结果写回及原版回退。 |
| 类型与扩展注册 | 声明原版和模组类型、输入字段、条件、部件、校验与预览样例，避免受 MetaType 限制。 |
| 方案解析 | 合并世界默认、文化结构、语言词库、启用包与玩家覆盖，给出有效配置和来源。 |
| 命名执行 | 对只读请求运行规则、取词、校验和有限重试，返回结果及诊断；不直接修改游戏对象。 |
| 世界状态与继承 | 保存世界配置、文化和语言调整、已确定姓氏与必要组成部分，处理出生、分化和对象复制。 |
| 编辑与预览 | 管理草稿、可视化编辑、来源和冲突展示；预览复用执行逻辑，应用时更新生效配置。 |

文化与语言来源及主要命名生命周期已确认，详见[来源表](设计讨论.md#命名时的文化与语言来源)与[生命周期](设计讨论.md#命名生命周期)。模块边界与调用流程的进一步建议见[架构草案](架构与执行流程草案.md)。出生初始化的准确接入点、命名状态复制、格言所有者的具体来源和未列出的其他事件仍需细化。

## 后续验收条目

以下是需要实现后验证的场景，目前均未执行：

| 场景 | 核对目标 |
| --- | --- |
| 有文化与无文化生物首次命名 | 使用适用方案，缺少文化或语言仍有有效回退；每个实际物种及其变体均有默认覆盖。 |
| 出生后延迟显示名字 | 继承选择与出生文化一致，首次读取前后不重复抽姓。 |
| 未取姓的亲代、单亲与无亲代 | 正确区分未初始化与不使用姓氏，兄弟姐妹不会因父母尚未命名而各自随机继承。 |
| 社会对象与新文化、新语言 | 命名输入完整，初始化不循环，分化后的配置按已确认规则独立保存。 |
| 联盟、战争、格言和无制造者装备 | 接入补齐调用处信息，缺失输入按既定路径回退。 |
| 军队与亚种 | 独立入口确实被覆盖，编号与避重行为符合类型要求，不出现原版后缀再次覆盖生成结果。 |
| 重铸、亡灵转换、升格与克隆 | 自动重铸名按结果重取，手改装备名保留；亡灵转换和升格保留个人名，新亚种另行命名；克隆复制姓名、姓氏及组成部分。 |
| 世界名与玩家名 | 没有文化或语言对象时可以生成，新世界默认配置的初始化顺序正确。 |
| 手改、切包、读档与预览 | 已有名字保留，保存恢复一致；预览不改变世界名字、姓氏、配置或随机状态。 |

静态入口清单还需与游戏运行时的生物资源列表、可用内容及实际触发记录交叉核对，才能成为完整覆盖的验收结论。
