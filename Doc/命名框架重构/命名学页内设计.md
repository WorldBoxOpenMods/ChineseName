# 命名学页内设计

> 历史方案。下一版讨论见[命名学字形拓展方案](命名学字形拓展方案.md)。

2026-11-18。人名和城市名直接在文化档案的「命名学」里编辑。本方案取代独立「命名规则」窗口的布局。上一版实现和原型留作交互记录。[命名学部件编辑方案](命名学部件编辑方案.md)

## 界面

沿用原版的页面顺序。顶部显示名字样例，中间保留单位、家族、氏族、城市和国家的分类图标，下面是排列条和选中项的编辑区。单位和城市直接显示当前命名规则的卡片。示意图用文字标出控件在原版页面的位置。

```text
文化档案 · 命名学
┌──────────────────────────────────┐
│ 中原话 ▾   欧阳青          ⟳  对照 │  样例区
│ 河谷话 ▾   欧阳岚                 │  开启对照才显示
├──────────────────────────────────┤
│ 单位    家族    氏族    城市    国家 │  原版分类图标
│         [姓氏] [名]        [+]    │  排列条
│ ──────────────────────────────── │
│ 姓氏    继承：父系优先 ▾           │  只展开选中的部件
│ 新取姓氏    姓氏词库 ▾             │
│                      应用    …   │  有改动时显示
└──────────────────────────────────┘
```

命名包和当前文化决定进入时显示的规则。玩家在卡片上编辑顺序、词库和固定文字。点卡片或样例里的文字，在原版词组位置编辑对应部件。能换序的卡片可以拖动，也可以用键盘选中移动按钮。`+` 提供可添加的部件，例如城市后缀和人名中间名。规则条件、分隔符和预览输入收进 `…`，原地展开。

`…` 里的「编辑原版卡片」打开当前分类的原版排列条、特殊字形和构建字形。按原版习惯在字形区选词组，在排列条上拖动、点击移除。词组来源可以是手填原版词组，也可以绑定姓氏、名字或地名等部件。原版导入模板和随机卡片作用于当前卡片草稿。

## 三个编辑例子

| 样例 | 页内操作 | 预览效果 |
| --- | --- | --- |
| **欧阳青** | 点样例中的「欧阳」或「姓氏」卡片，选父系优先、母系优先、随机选一方或新取姓氏。点「青」改名字的字数和词库。双字名可以分别编辑首字和末字。 | 固定模拟继承姓氏「欧阳」后，对照中原话和河谷话可得到「欧阳青／欧阳岚」。已继承的「欧阳」作为一个完整部件保留。 |
| **澄江府** | 点原版「城市」图标，用 `+` 加上后缀。点「府」编辑后缀，可填固定字、使用文化词表、选词库或设为可省略。 | 将固定后缀改成「州」，两行分别变成「澄江州／栖岭州」。点「栖岭」可以追溯河谷话使用的地名词库。 |
| **约翰·史密斯** | 在单位分类分别给姓氏和名字选词库，拖动姓氏到名字之后。用 `…` 设定中文间隔号和英文空格，再切换预览写法。 | 英语在默认顺序下显示 `John Smith` 或「约翰·史密斯」。法语可对照 `Jean Martin` 或「让·马丁」。缺少译名的部件沿用原文，来源详情标明缺译名。 |

顶部默认只显示一行样例和一个预览语言。点「对照」在同一块区域展开第二行。两行共用本次样例编号、规则、写法和模拟亲代条件。点样例文字同步高亮对应的卡片，底部显示实际来源，例如「河谷话 · 地名词库」「文化固定词」或「继承的完整姓氏」。原版特殊卡片合并文字时，按生成结果能追溯的范围显示来源。

两行样例用完顶部原有的预览空间，分类图标和卡片的位置由此保持稳定。窄窗优先完整显示样例，长语言名称缩写并在悬停或键盘聚焦时显示全名。详细来源留在选中项的编辑区。

## 卡片与生效规则

安装的命名包和已应用的文化设置决定命名规则。`…` 里的「用当前部件排卡片」可以从编辑中的部件生成原版排列，预览顺序和绑定后再应用。「停用原版卡片」恢复部件编辑，并保留原版排列草稿。原版模板、词组和特殊卡片继续用原版格式保存。框架另外保存语义绑定和实际做过的覆盖，未编辑的内容随命名包更新。

有修改时，在词组区下沿显示「应用」。`…` 收纳保存草稿、放弃修改和局部恢复。切换单位与城市、退出文化页再返回，保留各自的草稿。显式保存的草稿随存档保留。应用只提交当前文化和分类里的编辑。预览用同一条生成路径，使用自己的随机状态。无效卡片会在样例区显示原因，例如「这个排列缺少名字」，应用按钮也在原位提示需要修正。已取好的名字和已经继承的姓氏由原对象保存。

## 接入与验收

界面放在已有的 `OnomasticsTab`。原版分类、样例文字、卡片排列和词组编辑都有各自明确的控件，可在这些位置挂接适配器。结构化卡片只是框架规则的显示和操作入口，原版卡片模式才读写 `OnomasticsData`。生成、语言词库、继承和文化演化继续走命名服务。原版的模板下拉负责加载原版模板。旧存档里已经选择的规则引用继续读取，页内编辑只保存具体改动。全局「命名管理」中的文化规则链接也定位到这个页内分类。[原版命名学控件](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/OnomasticsTab.cs) · [原版模板选择](../../../Cultiway/.GameSource/Assets/Scripts/Assembly-CSharp/OnomasticsDropdown.cs)

首批接单位与城市。已注册的模组类型后续可从分类末端的「更多」进入，复用排列条、来源编辑、语言对照和草稿。类型定义提供可编辑部件、选项与预览所需输入。Cultiway 的法术可以显示「元素」「形态」等部件，姓氏继承或地名后缀只在支持这些能力的类型里出现。

- 从同一份文化档案完成三个例子的选卡、文字输入、对照、编辑原版卡片、应用和读档。检查应用前后实际生成结果，以及旧版草稿和卡片能否继续编辑。
- 用原版卡片导入、换序和绑定词组。检查切回部件编辑再返回时，草稿和选中项能恢复。手动删掉一个必需词组，确认问题直接出现在样例区。
- 在游戏内核对最小窗口下的命中区域、键盘选中和拖动。对照关闭时只显示一行样例和选中卡片的字段。原版其他分类的编辑和预览照常进入。
