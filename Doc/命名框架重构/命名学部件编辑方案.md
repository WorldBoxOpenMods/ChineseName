# 命名学部件编辑方案

2026-11-18。本文细化文化档案「命名学 → 命名规则」的编辑方式。配套页面使用示例规则和词库，可直接在浏览器离线打开。[部件编辑交互原型](原型/命名学部件编辑原型.html)

本页记录独立窗口版的设计与实现。新版布局直接复用原版命名学的样例区、排列条和词组编辑区。[命名学页内设计](命名学页内设计.md)

## 游戏中的界面

人名和城市名从文化档案的对应「命名学」分类进入。游戏版复用 WorldBox 的滚动窗口、返回历史和原版控件贴图，沿用原版窄窗尺寸。原型的并排布局在游戏里拆成「部件」「语言对照」「高级」三页。选中语言对照里的某个部件会打开对应的编辑项，并显示该语言的词库或继承来源。

高级页选择「原版卡片」后可以打开原版命名学界面。卡片排序、增删和词组输入沿用原版操作。返回「命名规则」后可以检查词组绑定和预览，再决定应用或保存草稿。

## 共用一个编辑页

页首选择命名类别和规则。当前文化从入口带入。名字以可点击的部件按最终顺序排列，点中一段就编辑这一段。右侧预览在相同规则和输入条件下并列展示两种语言，并允许点中样例中的任一段，查看这段的来源。窄窗将两列语言预览折成上下排列，编辑区上方保留名字摘要。

类别负责定义常用部件及设置，页面统一提供部件选择、来源编辑、预览、应用和恢复。每条规则分别保留草稿。切换类别、写法或预览语言时保留未应用修改。应用只保存当前规则，影响之后的新名字。已经生成的名字和已经确定的姓氏随对象保存。

| 类别 | 默认展示 | 专属设置 |
| --- | --- | --- |
| 人名 | 姓氏、给名。按规则显示中间名等额外部件。 | 继承方式、姓氏顺序、给名长度、是否采用中间名、分隔方式。 |
| 城市名 | 地名主体和后缀，或单个完整地名部件。 | 完整地名与组合命名切换。后缀可以固定、抽取或省略。 |
| 模组类型 | 按注册的部件名称和顺序显示，例如法术部件「元素」「形态」「结尾」。 | 类型可声明选项、必填条件、预览输入和样例。未声明专用控件的类型用通用部件编辑器。 |

词库选择器优先展示用途和可读名称，词库 ID 只在来源详情里展开。允许部件使用语言词库、文化自己维护的词表、固定文字或类型提供的输入。只有声明了相应能力的部件才出现「继承」「可选」等设置。默认每次只展开选中部件，复杂规则仍能在高级设置中编辑全部字段。

## 三条编辑路径

| 示例 | 怎么编辑 | 对照时应看到什么 |
| --- | --- | --- |
| **欧阳青** | 点「欧阳」选择父系优先、母系优先或随机继承，并为需要新取姓氏的角色指定词库。点「青」换给名词库，选择单字、双字或混合。双字可独立指定首字和末字来源。 | 固定一个模拟继承的姓氏「欧阳」，两种语言可分别生成「欧阳青」与「欧阳岚」。点「欧阳」可追溯到继承，点「岚」可看到语言和词库。 |
| **澄江府** | 点「澄江」调整地名主体的词库，点「府」换成固定「州」、选择文化词表或省略后缀。另有「完整地名」结构，整个结果由一个词库提供。 | 原规则可对照「澄江府／栖岭府」。把固定后缀改成「州」后，两边后缀一起变化，主体仍由各自语言决定。 |
| **约翰·史密斯** | 点「约翰」换给名来源。点「史密斯」看姓氏来源。可独立选择姓在前或姓在后、是否插入中间名，以及显示写法。 | 英语风格规则的初始顺序为给名在前。可显示「约翰·史密斯」或 `John Smith`。英语和另一种语言也可在相同顺序下提供不同的词库。 |

预览语言与显示写法是独立选择。语言决定从哪里取词，规则决定姓氏顺序，写法决定同一个词显示为原文还是命名包提供的中文译名。使用中文显示时缺译名就显示原文，并在该部件来源标出。已继承的文字整段使用，改写法也保留原样。分隔符跟随规则，默认中文人名紧接，英语风格的中文写法以间隔号分隔，原文以空格分隔。

对照使用同一个样例编号和相同条件。两边即使抽到相同的名字，仍能检查每段来自哪里。预览可明确锁定一个继承姓氏，也可让继承策略按两位模拟亲代工作。预览抽取、选中的部件和预览语言都属于浏览器样例状态。应用只提交命名规则本身。

## 高级设置和原版卡片

「高级设置」展开后可以选择使用结构化部件或原版卡片。两种布局分别保存，切换时在草稿上生效。卡片排列为独立列表，每个词组可以绑定一个语义部件，沿用该部件的来源配置。例如将「词组 1」绑定「姓氏」，将「词组 2」绑定「给名」。在游戏里继续使用原版卡片控件进行排列和配置。浏览器用可移动的列表行演示卡片排列、绑定、增删和回退提示。

预览标题显示实际使用的命名方式，卡片样例的部件来源同时标出词组和绑定。若选了姓氏继承，每种卡片排列须恰好使用一个姓氏组。卡片缺失必需部件时，在预览中同时显示回退结果和具体原因，修正卡片后才能应用。原版的拼写操作保留原义。首字母大小写等能力留在高级模式，普通部件编辑无需关心它们。

## 浏览器走查

同一入口依次验证三个示例的基础编辑、同一条件下的语言对照、切换原版卡片和恢复结构化布局。补查键盘选中部件、切换示例后草稿仍在、回退原因、保存范围和窄窗对照。原型用固定词库和可重复的样例编号展示行为。原版复杂卡片和第三方模组接口的实际效果留待游戏接入验收。

在独立 Chrome 会话中通过 45 项检查，覆盖复姓原样保留、给名首末字独立选库、城市后缀与完整地名切换、英文原文和中文译名独立于姓氏顺序、缺译名提示，以及三条示例各自的卡片编辑。检查了 1440、960、720、610 和 360 像素宽度。

走查中发现两处需要调整。输入后直接点击下一部件时，应更新预览并保留点击目标，所以文字输入只刷新受到影响的内容。卡片顺序接管后，基础区改为显示「调整卡片」入口，姓氏位置和城市命名结构的快捷选项在部件规则中显示。两项修正均已复测。[桌面截图](原型/截图/命名学部件-桌面.png) · [窄窗截图](原型/截图/命名学部件-窄窗.png)
